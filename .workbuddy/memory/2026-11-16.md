  Gin 是次选（生态最大但要自己拼 session/模板/多库）。

  beego 版打 tag `v1-beego` 留档，两套并行、共用同一套数据库。接口行为与内容包 URL
  前缀（/static/content/）刻意与 beego 版一致，切换不影响 App。
- **通用 CRUD 改成注册表驱动**（本次最重要的架构升级）：`internal/registry/tables.go`
  一段配置 = 一张可管理的表（列/类型/筛选/校验/多值关联），列表页搜索筛选编辑弹窗

- 词库数据沿用 beego 版灌入的 7201 词；发布内容包 v2（845KB，md5 与文件字节一致已验证）。
- GoFrame 实测踩坑（都是官方文档不显眼处）：
  1. **MySQL 驱动在 contrib**，必须 `_ "github.com/gogf/gf/contrib/drivers/mysql/v2"`，
     否则报 "cannot find database driver for mysql"；
  2. **RouterGroup 不接受空 pattern**：`group.GET("")` 会把路由拼成 `/admin/GET:`，
     首页 `/admin` 404。解法 `s.BindMiddleware("/admin", mw, handler)`；
  3. `Fields("COALESCE(MAX(x),0) AS v").Scan(&n)` 别名映射不上，标量查询用
     `db.GetValue(ctx, sql, args...)` 才可靠；
  4. 端口冲突预检：goproxy.cn 不可达，阿里云 goproxy 镜像可用（go env GOPROXY 已配）。
- 端到端验证全过：登录/鉴权 401、CRUD 列表（kw+f_cefr=82 条，与 beego 版一致）、
  关联表筛选、新增（重复唯一键→友好报错；必填校验）、更新重建关联、级联删除、

## 推送 admin_platform_v2 到 GitHub

- 远程：`git@github.com:lightonthekey/app_admin_platform.git`，main 分支，28 文件（提交 9293ca3）。
- **本机 git 走 HTTPS 推 GitHub 会失败**，原因不是仓库问题，而是环境变量里的代理：
  `http_proxy/https_proxy=http://127.0.0.1:14994`，git 走它会报
  `CONNECT tunnel failed, response 502` 或 `Empty reply from server`（代理不支持 github 的 CONNECT）。
  两个解法：① 命令前 `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY`；
  ② **改用 SSH 地址最稳**（ssh 不读 http_proxy）。本机 `~/.ssh/id_ed25519` 已绑定
  GitHub 账号 lightonthekey，`ssh -T git@github.com` 直接返回 `Hi lightonthekey!`。
  以后推 GitHub 一律优先 SSH，别用 HTTPS。
- 该仓库（app_admin_platform）用未认证 curl 查 API/网页都是 404 → 说明是**私有仓库**，
  不要据此判断"仓库不存在"。

## 一、目标

**保留 engmatch 的音效与纸片爽感，但让配对成功的词「留下来」。**

三条不可动摇的原则：

1. **这是学习卡片，不是消除游戏** —— 每个配对的词都必须让用户看得清、记得住。
   配对成功不是「消除」，是「一次成功的记忆曝光」。
2. **轻快有爽感** —— 反馈要快、要脆、要有声音。
3. **只重做界面与动效** —— 配对判定、进度记录、错词回流的规则一律不动。

## 三、核心改动：顶部「巩固台」

### 3.1 为什么这么做

记忆需要重复曝光。配对成功的那一刻，是这个词记忆强度最高的瞬间，结果我们
用 0.5 秒把它销毁了 —— 等于把最有价值的教学时机浪费掉。

巩固台的作用：把刚才配对的词**留在视野里**，用户随时能回看，
不用「凭记忆回想我刚才配了什么」。

### 3.2 形态（推荐方案：融合式）

棋盘上方一条固定区域，横向排布，最多 **3 个**词对。

1. 配对成功 → 两张卡合拢，沿弧线**飞到巩固台**（约 340ms）
2. 落位后该槽位**放大字号 + 绿框高亮，保持 2 秒**（能看清英文、中文）
3. 2 秒后高亮褪去，变回普通样式**常驻**
4. 台子已满 3 个时：**整条轨道向左平移一格**（300ms）——
   最左那个滑出容器，新词从右边缘滑进来，中间两个只平移、文字不变

为什么 3 个：屏幕宽度够放，且正好是短期记忆的块数（3~4 chunk）。
用户能一眼扫到「刚才连着的三个词」，形成一小段语境。

> 实现备注 1：槽位只有 78dp 高，装不下完整卡片（英文+音标+中文三行）。
> 所以「停留」不是把大卡片钉在顶部，而是**把该槽位放大加亮 2 秒**。
> 音标在棋盘卡上已经看过一遍，这里只强化「英文 ↔ 中文」的对应。
>
> 实现备注 2（为什么不用「固定三格换字」或「1-2-3 轮流替换」）：
> 前者是一次换三张，画面整体闪一下，眼睛要重新读三个词；
> 后者虽然每轮只换一张，但三个位置轮流变，**看不出谁最新**，
> 巩固台就失去了「刚配对的是哪个」这个意义。
> 左移的本质是一条队列：位置即时间顺序，左边最旧、右边最新，一眼可读。
> 视觉上也只动了「一条」而不是「三个点」。


### 3.3 备选方案（如果你觉得融合式太复杂）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 纯标签 | 不飞行，直接在巩固台插入迷你标签，常驻 3 个 | 实现最简单，最稳 | 「看一眼」的时间短，不够巩固 |
| B 纯停留 | 完整卡片飞到顶部，停 2.5s 后淡出，不留存 | 停留最长 | 停留完就没了，回看不了 |
| **C 融合（推荐）** | 先停 2s，再收成标签常驻 | 兼顾「看够」和「能回看」 | 动效最复杂 |

### 3.4 新时序表

| 时刻 | 发生什么 |
|---|---|
| 0ms | 点第二张卡 |
| 0–140ms | 判定缓冲（太短会看不清点了哪两张） |
| 140ms | 两卡变绿 + 轻弹一下；底部显示 `✓ milk = 牛奶`；**立即解锁** |
| 140–480ms | 绿卡原地停留，用户已可点下一组 |
| 480ms | 两卡合拢 → 起跳飞向巩固台（340ms 弧线）；纸屑从起飞点炸开；音效 |
| 480ms | 棋盘原位**并行**补新词（pop 浮现，不打断飞行） |
| 820ms | 落到巩固台，弹一下（1 → 1.12 → 1） |
| 820–1120ms | 若台子已满：整条轨道左移一格，最旧的滑出、新词从右边滑入 |
| +2000ms | 绿框高亮褪去，变回普通样式常驻 |

**关键**：从 140ms 起就不再锁操作。飞行、补位、巩固台落位全部是背景动画，
用户手快可以一路配下去。

### 3.5 布局影响

现在一屏 5 行卡片几乎顶满屏幕（行高太大，视觉很闷）。
加了巩固台之后：

- 棋盘 **5 行 → 4 行**（4 对 8 张卡）
- 腾出的高度给巩固台（约 88dp）+ 卡片之间的呼吸空间
- 顶部「5 对 5 配对」和进度条 `1/20` 信息重复 → 合并成一条

### 3.6 补位：英文固定，中文整列重排

参考页每次都 `renderBoard()` 整盘洗牌，8 张卡全换位置，眼睛要重新扫一遍。

改成：

- **英文列固定**：哪格消失就补哪格，位置永远不动，当锚点用
- **中文列整列重排**：每配对一对，中文全部重新打乱一次

这样兼顾了两件事：

1. 英文位置稳定 → 学习时能建立空间记忆，不用每次重新找
2. 中文位置每次都变 → 靠位置蒙不了，也顺手消除了「同一行左右同词」的白送格
   （重排时显式保证没有任何一行左右是同一个词）

比「整盘重排」轻一半，也比「全部原地不动 + 单独处理同行」的规则简单得多。

App 现在完全没有音效（只有 `HapticFeedback` 震动）。参考页的音效用户是满意的，

| 场景 | 参考页实现 | 落地方式 |

- 用 Python 正弦波 + 指数包络生成 wav，放 `assets/audio/`

- 顶部放一个静音开关（记忆到本地），默认开启

## 七、验收标准

原型阶段你只需要判断四件事：

1. 配对成功后，我**愿不愿意多看一眼**那张卡？
2. 连打五对，**手感是顺的还是被卡的**？
3. 顶部的词我**能不能随时回看**刚才配了什么？
4. 声音和纸屑出现时，**有没有"爽"一下**？

Flutter 移植后补自动化测试：巩固台最多 3 个、挤出顺序、补位原位、
连打不锁交互、整局能结算。

## 九、已确认的结论

1. **巩固台形态**：融合式 —— 落位后绿框高亮 2 秒，常驻 3 个，满了整条左移。
2. **棋盘行数**：5 行 → 4 行，腾出来的高度给巩固台。
3. **中文卡副行**：**保留完整释义**（`detail`，最多 2 行，超出用省略号）。
   自己玩的时候会看释义，所以不做「缩略成 2 条义项」。
4. **代码状态**：当前实现在 `c1e8094` 存档；v2 已按本文件从设计稿重写 `lib/pages/match.dart`。

## 十一、二轮调整：更「干净」的配对反馈（2026-11-18，原型已改）

用户玩过之后的三个意见，改的都是 `design/game-v2.html`：

1. **配对成功不再「抖一抖」**
   原来两张卡先加 `.hop`（-9px 回弹）再飞走，游戏里 20 对下来这个动作很吵。
   现在去掉 `.hop`，判定完只留一帧绿色、`flyStart` 从 480ms 压到 40ms —— 对完就直接收走。
   反馈交给三处：两卡中点炸开的纸屑、飞向巩固台的合拢、巩固台那一格 `pop`。

2. **巩固台不再丢词：整关都留着，可以横滑回看**
   一关只有 20 个词，把「常驻 3 格 + 满了整条左移」换成一条**横向滚动轨道**：
   - 槽宽 106dp（第十二节改成按台子宽度自适应），一屏正好 3 格
   - 开局 3 个虚线坑当占位，填满后一直往右加格，最多 20 格（一关 10 对）
   - 新词落位时轨道跟到最右；用户往回翻（不在最右）就不抢他的位置，
     靠 `shelfPinned` 判断，滚回去自己看刚学的词不会被打断
   - 标签从「刚配对」改成「本关已学」，右侧计数 `8 / 12 对 · 左右滑动查看`
     （第三轮把这行整个删掉、名称印进第一张卡片，见第十二节）
   - 因此删掉了 `landOnShelf` 里的左移动画、`SHIFT_MS`、`compact()` 收拢逻辑

3. **最后 4 对不再消失，原地置灰**
   原来词池空了以后每对配完就清一格、再把剩下的收拢到底部，收尾是一屏错开的虚线空格，
   看着像界面出错了。现在：
   - 判定条件很干净：**词池 `queue` 空了 = 盘上这 4 对就是最后 4 对**
     （一关 10 对、一屏 4 对，前 6 对配完刚好补满最后一屏）
   - 这 4 对配完不再飞、不再补位，两张卡原地加 `.done`：灰底 + 淡灰字 + 右上角淡对勾
   - 结算判定从「盘空了」改成 `matched === total`（`checkEnd`）
   - 结算时棋盘从 `.18` 改成 `.55` 透明度：后面是一整盘学完的词，正好当背景

截图：`shots/g2-mid.png`（开局 / 巩固台刚起步）、`g2-end.png`（8/12，轨道已满可横滑）、
`g2-grey.png`（11/12，配对过的原地置灰）、`g2-finish.png`（结算）。

## 十二、三轮微调：标题、去滚动条、槽宽自适应（2026-11-18）

又两条意见，都只动 `design/game-v2.html`：

1. **空态三张背景卡，第一张上面印「巩固台」**
   开局那三个空框太素，看不出这一条是干什么的。**不另起一行标题** —— 直接把
   「巩固台」印在**第一张卡片内的上方**（`.slot.ph::before`，11px/600、`#A9A3BE`）：
   - 卡片本身就是背景板，字压在它上面，整块看着仍是一条台子，不占额外高度
   - 卡片一旦被词填上，`paintSlot` 重设 `className`，`ph` 丢掉，字自动消失
   - 因此外面原来那行「本关已学 / 配对成功的词会停在这里」整行删掉
     （已学几个看顶部进度条 `3 / 12` 就够，不必再说一遍）

2. **不再出现横向滚动条**
   原来用 `overflow-x: auto` + 隐藏滚动条样式。桌面 Chrome、部分安卓 WebView、
   iOS 的 overlay 滚动条都会在滑动时画一条出来，手机应用里已经很少见这种控件。
   现在改成**自己接管拖动**：
   - `.shelf { overflow: hidden; touch-action: pan-y; }`，轨道 `transform: translateX()`
   - `pointerdown / pointermove / pointerup`（鼠标和手指一套逻辑），松手按最后一帧速度外推
     `min(0, -v*170)` 最多 160px，再缓动收尾
   - `shelfX / shelfMax / shelfPinned` 三个状态替代原来的 `scrollLeft / scrollWidth`
   - 新词落位照旧「贴着最右才跟拍」，用户往回拖过之后不抢位置
   - 因此 `shelfAutoScroll`、`shelfScrollTimer`、scroll 监听全部删掉，逻辑反而更短

   > 两个量出来的坑：
   > 1. `shelfMax` 要用**可视内容宽**（`clientWidth − 左右 padding`），拿 `clientWidth`
   >    会少推 12px，最后一格永远露一条白边贴不满右边缘。
   > 2. 台子 342 宽、三格 106 + 两道 6px 间隙 = 330，右边会剩 12px 灰缝，看着像没对齐。

3. **槽宽自适应**：`flex: 0 0 var(--slotW)`，`--slotW = (可视宽 − 12) / 3`，
   由 `layoutSlots()` 在开局和 `resize` 时算。一屏永远正好 3 格、铺满不留缝，
   第 4 格起往右长，拖动时才露出前面被切掉的格子。

截图已按新样式重出：`shots/g2-start|mid|end|grey|finish.png`。

## 十三、同步到 Flutter（2026-11-18，`lib/pages/match.dart`）

原型三轮调整全部落到 Dart，顺带把「巩固台」这张牌重做了一遍。

| 原型 | Dart |
|---|---|
| 配对成功不抖 | 删掉 `_hop` 控制器和 `ok` 的位移曲线，`_T.flyStart` 480 → **40ms** |
| 巩固台整关留词、可横拖 | `ScrollController` + `ListView.separated`（横向），`_shelf` 不再 `removeAt(0)` |
| 不出现横向滚动条 | `_NoBarScrollBehavior`（`buildScrollbar` 直接返回 child），桌面端也不会自动加条 |
| 最后 4 对原地置灰 | `_Card.done` 状态；`_retire` 里 `_queue.isEmpty` 就走置灰分支 |
| 空态第一格印「巩固台」 | `_shelfSlot(placeholder: ...)`：第一格空着时居中显示 11.5px / w400 / `#ACA6C1` |
| 收尾按配对数量判结束 | `_checkEnd` 从「盘空了」改成 `_done < _total` 就返回 |

**两个只有真正跑起来才会暴露的坑：**

1. **不能用 `ScrollController.addListener` 判「用户往回翻了」**
   新词落位后轨道变长，`ScrollPosition` 会因为 `maxScrollExtent` 变化**自己发一次通知**，
   那一帧 `pixels` 还停在旧的最右，于是被判成「用户手动翻回去了」，
   `_shelfPinned` 直接变 false —— 从第 4 个词起就再也不跟拍（截图里轨道一直停在最左）。
   改成监听 `UserScrollNotification`：它只在手指拖 / 惯性滚动时发，程序 `animateTo` 不发。

2. **懒加载列表的 `maxScrollExtent` 是估算值**
   `ListView` 只量已构建的子项，一次 `animateTo(maxScrollExtent)` 可能只滚到「估算的终点」，
   滚完发现真实终点又变远了。所以 `_scrollShelfToEnd()` 滚完再比一次，还有差距就补滚
   （第二次起 120ms，深度上限 3）。

另外：**收尾置灰时要把 `c.ok` 一起清掉**，否则 `done` 分支永远排在 `ok` 后面，

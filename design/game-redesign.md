## 一、目标

**保留 engmatch 的音效与纸片爽感，但让配对成功的词「留下来」。**

三条不可动摇的原则：

1. **这是学习卡片，不是消除游戏** —— 每个配对的词都必须让用户看得清、记得住。
   配对成功不是「消除」，是「一次成功的记忆曝光」。
2. **轻快有爽感** —— 反馈要快、要脆、要有声音。
3. **只重做界面与动效** —— 配对判定、进度记录、错词回流的规则一律不动。

参考页：`https://tooldeer.com/engmatch.html`

| 项 | 参考页现状 | 我们怎么处置 |
|---|---|---|
| 玩法 | 点左一张 + 点右一张判定 | **保留** |
| 纸屑 | WebAudio 无关，Canvas 逐帧物理 | **保留**（已移植到 `lib/confetti.dart`） |
| 音效 | WebAudio 实时合成（660+880Hz 双音） | **补齐**（App 目前只有震动，没有音效） |
| 连击飘字 | 32px 绿色文字向上飞出 | **补齐** |
| 成功反馈 | 放大 1.12 → 缩到 .86 + 透明，**0.52s 就没了** | **改掉** ← 本次核心 |
| 补位 | `refillPair()` 整盘重新洗牌 | **改掉**，保留原位（见 3.6） |

参考页的成功动画（`emGood`），问题就在最后一行：

```css
@keyframes emGood {
  0%   { transform: scale(1);    opacity: 1; }
  40%  { transform: scale(1.12); }      /* 只弹了一下 */
  100% { transform: scale(.86);  opacity: 0; }   /* 0.52 秒后消失 */
}
```

用户的原话：「选对之后马上就消失了，会有一种刚刚不知道选了啥的感觉」。

## 三、核心改动：顶部「巩固台」

### 3.1 为什么这么做

记忆需要重复曝光。配对成功的那一刻，是这个词记忆强度最高的瞬间，结果我们
用 0.5 秒把它销毁了 —— 等于把最有价值的教学时机浪费掉。

巩固台的作用：把刚才配对的词**留在视野里**，用户随时能回看，
不用「凭记忆回想我刚才配了什么」。

### 3.2 形态（推荐方案：融合式）

棋盘上方一条固定区域，横向排布，最多 **3 个**词对。

1. 配对成功 → 两张卡合拢，沿弧线**飞到巩固台**（约 340ms）
2. 落位后**保持完整卡片形态停留 2 秒**（能看清英文、音标、中文）
3. 2 秒后收成紧凑标签（`milk · 牛奶`），常驻
4. 再来新词时，最旧的向左滑出淡出，腾出位置

为什么 3 个：屏幕宽度够放，且正好是短期记忆的块数（3~4 chunk）。
用户能一眼扫到「刚才连着的三个词」，形成一小段语境。

### 3.3 备选方案（如果你觉得融合式太复杂）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 纯标签 | 不飞行，直接在巩固台插入迷你标签，常驻 3 个 | 实现最简单，最稳 | 「看一眼」的时间短，不够巩固 |
| B 纯停留 | 完整卡片飞到顶部，停 2.5s 后淡出，不留存 | 停留最长 | 停留完就没了，回看不了 |
| **C 融合（推荐）** | 先停 2s，再收成标签常驻 | 兼顾「看够」和「能回看」 | 动效最复杂 |

### 3.4 新时序表

| 时刻 | 发生什么 |
|---|---|
| 0ms | 点第二张卡 |
| 0–140ms | 判定缓冲（太短会看不清点了哪两张） |
| 140ms | 两卡变绿 + 轻弹一下；底部显示 `✓ milk = 牛奶`；**立即解锁** |
| 140–480ms | 绿卡原地停留，用户已可点下一组 |
| 480ms | 两卡合拢 → 起跳飞向巩固台（340ms 弧线）；纸屑从起飞点炸开；音效 |
| 480ms | 棋盘原位**并行**补新词（pop 浮现，不打断飞行） |
| 820ms | 落到巩固台，弹一下（1 → 1.12 → 1） |
| +2000ms | 收成紧凑标签常驻；巩固台超过 3 个则挤出最旧的 |

**关键**：从 140ms 起就不再锁操作。飞行、补位、巩固台落位全部是背景动画，
用户手快可以一路配下去。

### 3.5 布局影响

现在一屏 5 行卡片几乎顶满屏幕（行高太大，视觉很闷）。
加了巩固台之后：

- 棋盘 **5 行 → 4 行**（4 对 8 张卡）
- 腾出的高度给巩固台（约 88dp）+ 卡片之间的呼吸空间
- 顶部「5 对 5 配对」和进度条 `1/20` 信息重复 → 合并成一条

### 3.6 补位固定原位

参考页每次都 `renderBoard()` 整盘洗牌，视觉上是「全部卡片闪一下换位置」。
改成：**消失哪格就补哪格**，只换文字不挪位置，眼睛不用重新扫桌面。

唯一例外：如果配对的两张正好在同一行，补进去会被「同行白送」
（用户闭眼点那一行就必中），此时右列错开一格。

## 四、视觉规范

沿用参考页的轻快配色，比现在更亮、更脆：

| 元素 | 规格 |
|---|---|
| 卡片底 | 纯白 `#FFFFFF`，无边框或极浅描边，圆角 14 |
| 卡片文字 | 英文 20px/600 + 音标 11px `#999`；中文 20px/600 + 释义 11px `#999` |
| 选中 | 底色 `#E8F8EE`、边框 `#58CC02`、文字 `#3A9E00`、抬起 2px |
| 配对成功 | 同选中配色，加强绿色光晕 |
| 配错 | 底色 `#FFEBEB`、边框 `#FF4B4B`，左右抖 5px（不要上下颠） |
| 巩固台 | 浅灰底 `#F4F5F7`，圆角 12，词对之间细分割线 |
| 背景 | 目前是浅紫灰，可保留；参考页是纯白 |
| 主色 | `#58CC02`（Duolingo 绿）|

**要砍掉的**：中文卡副行现在显示 `n.水体，水面…` 这种半截释义，是纯噪音。
改成只显示词性（`n.`）或干脆不显示，把版面让给主词。

## 五、音效

App 现在完全没有音效（只有 `HapticFeedback` 震动）。参考页的音效用户是满意的，
按它的参数复刻：

| 场景 | 参考页实现 | 落地方式 |
|---|---|---|
| 配对成功 | `beep(660,.12) + beep(880,.12,delay:.12)` 双音 | 合成 2 个短 wav |
| 连击里程碑（3、5、10…） | 523/659/784/1046 四音阶 | 合成 1 个 wav |
| 配错 | 300Hz + 180Hz 锯齿波 | 合成 1 个 wav |

- 用 Python 正弦波 + 指数包络生成 wav，放 `assets/audio/`
- 播放复用已有依赖 `audioplayers` 的 `AssetSource`，不引入新包
- 顶部放一个静音开关（记忆到本地），默认开启

## 七、验收标准

原型阶段你只需要判断四件事：

1. 配对成功后，我**愿不愿意多看一眼**那张卡？
2. 连打五对，**手感是顺的还是被卡的**？
3. 顶部的词我**能不能随时回看**刚才配了什么？
4. 声音和纸屑出现时，**有没有"爽"一下**？

Flutter 移植后补自动化测试：巩固台最多 3 个、挤出顺序、补位原位、
连打不锁交互、整局能结算。
